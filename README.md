# Fraud Detection — Anomaly Detection на финансовых транзакциях

## Цель проекта

 Цель проекта — построить и сравнить несколько подходов к детекции аномалий (мошеннических транзакций) на реальных данных, оформить решение через MLOps-слой (FastAPI + Docker).

**Датасет**: [Kaggle Credit Card Fraud Detection](https://www.kaggle.com/mlg-ulb/creditcardfraud) — 284 807 транзакций за 2 дня, 492 из них мошеннические (~0.17%). Признаки `V1...V28` — результат PCA-преобразования (исходные банковские поля скрыты по NDA), `Time` и `Amount` — единственные признаки с прямой интерпретацией.

**Модели для сравнения**: Isolation Forest, One-Class SVM, Autoencoder.

## Методология

### Валидационная стратегия: semi-supervised

Ключевое архитектурное решение проекта — модели обучаются **только на нормальных транзакциях** (`Class = 0`), фрод не участвует в обучении вообще. Это соответствует "родной" философии One-Class SVM и Autoencoder (обучиться на эталоне нормы, детектировать отклонения от него) и обеспечивает честное сравнение всех трёх моделей по единому протоколу.

Схема разбиения:

| Выборка | Норма | Фрод | Итого | % Class=1 |
| --- | --- | --- | --- | --- |
| train | 198 277 (70%) | 0 | 198 277 | 0% |
| val | 42 488 (15%) | 236 (50%) | 42 724 | 0.552% |
| test | 42 488 (15%) | 237 (50%) | 42 725 | 0.555% |

- `train` — только норма, модель учится эталону "нормального поведения".
- `val` — калибровка порога / подбор гиперпараметров (содержит фрод).
- `test` — финальная, ни разу не тронутая оценка (содержит фрод).

Фрод намеренно поделен 50/50 между val/test (а не пропорционально), т.к. его физически мало (473 записи после дедупликации) — на каждую выборку нужен разумный минимум примеров для нешумной оценки метрик.

### Метрики

Из-за экстремального дисбаланса классов (~0.17%) Accuracy неинформативна. Основная метрика — **PR-AUC** (Precision-Recall AUC), т.к. она не зависит от выбора конкретного порога и корректно отражает качество ранжирования при сильном дисбалансе.

## Прогресс

### EDA

Ключевые находки:

- **Дубликаты**: 1081 полный дубликат строк, из них 19 — среди фрод-класса (почти 4% от всех фрод-случаев). Удалены до train/test split во избежание data leakage.
- **Дисбаланс классов** (после дедупликации): 283 253 норма (99.83%) vs 473 фрод (0.17%).
- **Amount**: у фрода более широкое, менее предсказуемое распределение сумм — толще нижний хвост (гипотеза: card testing мелкими суммами) и выше верхний квартиль, чем у нормы. Медианы отличаются (22.0 vs 9.82), но диапазоны сильно пересекаются.
- **Time**: доля фрода среди транзакций резко возрастает в ночные часы (~2-4 утра) — почти в 10 раз выше среднего по датасету уровня. Правдоподобная гипотеза: владелец карты спит и не может оперативно среагировать.
- **V1...V28**: топ-5 признаков по |корреляции| с `Class` — V17 (-0.313), V14 (-0.293), V12 (-0.251), V10 (-0.207), V16 (-0.187). Boxplot подтверждает выраженный сдвиг медиан между классами при частичном перекрытии распределений.

### Train/Val/Test Split

Semi-supervised схема разбиения (см. таблицу выше). Сохранено в `data/processed/{train,val,test}.csv`.

### Feature Engineering

- `Hour` (час суток, из `Time`) -> циклическое кодирование `Hour_sin`/`Hour_cos` (решает проблему "23 и 1 час — разные по числовому значению, но близкие по смыслу"), исходный `Time`/`Hour` удалён.
- `Amount` -> `log1p(Amount)` (сильно искаженное распределение -> логарифмирование), исходный `Amount` удалён.
- `V1...V28` + `Amount_log` -> `RobustScaler` (устойчив к выбросам за счёт медианы/IQR вместо mean/std — в данных остаются легитимные экстремумы, которые не хотим "давить" как шум).
- Единый `ColumnTransformer`, обучен (`fit`) **только на train**, применён (`transform`) к val/test без переобучения — защита от data leakage.
- Артефакты: `X_{train,val,test}.csv`, `y_{val,test}.csv`, `models/column_transformer.pkl`.

### Baseline

Простая эвристика: $anomaly\_score = \sum{|scaled\_features|}$ по топ-4 признакам из EDA (V17, V14, V12, V10).

**Результат: PR-AUC = 0.739** на val.

Это точка отсчёта - модели должны заметно превзойти это значение, чтобы оправдать свою сложность.

### Isolation Forest (isolation_forest.ipynb)

Обучение только на `X_train` (semi-supervised), скор аномальности - инвертированный `score_samples()` (в sklearn более отрицательное значение = более аномальное, поэтому знак инвертирован для консистентности с остальными моделями).

**Диагностика curse of dimensionality**: с дефолтными гиперпараметрами (`max_samples=256`) PR-AUC на полных 31 признаках оказался неожиданно низким (0.282) - заметно ниже baseline. Проверка на урезанном наборе (только V17/V14/V12/V10) сразу дала 0.689 - подтверждение, что причина в размерности: случайные разбиения "теряются" среди 26 малоинформативных признаков. После увеличения `max_samples` до полного объёма train (вместо дефолтных 256 точек на дерево) и `n_estimators=500` результат на полном наборе признаков вырос до 0.55.

**Официальный результат (полный набор, 31 признак): PR-AUC = 0.55**
(вспомогательный эксперимент на 4 отобранных признаках: 0.77 - не участвует в основном сравнении, т.к. использует метки для отбора фичей)

### One-Class SVM (one_class_svm.ipynb)

В отличие от Isolation Forest, критично требует масштабирования, поэтому использован уже готовый `RobustScaler`.

Из-за квадратичной-кубической сложности обучения ($O(n^2) - O(n^3)$) обучение на полном train (198к строк) непрактично - использована случайная подвыборка 45 000 строк (только норма, риска потери редкого класса при сэмплировании нет).

Подбор гиперпараметров `nu` (доля допустимых margin errors на train, фактически регуляризатор компактности границы) и `gamma` дал умеренный прирост: с дефолтных настроек (0.24) до `nu=0.05, gamma='auto'` (0.32).

**Официальный результат (полный набор, 31 признак): PR-AUC = 0.32**
(вспомогательный эксперимент на 4 отобранных признаках: 0.79)

Наиболее сильно из всех моделей пострадал от размерности - ожидаемо, поскольку метод сильнее остальных опирается на метрику расстояния, которая теряет информативность в высокоразмерном пространстве.

### Autoencoder (autoencoder.ipynb)

Архитектура - полносвязный автоэнкодер для табличных данных:

```md
Input(31) → Dense(16)+ReLU → Dense(8)[bottleneck]
→ Dense(16)+ReLU → Dense(31)+Linear [reconstruction]
```

Ключевые решения:

- Линейная активация на последнем слое decoder - обязательна, т.к. признаки после `RobustScaler` симметрично принимают отрицательные и положительные значения; ReLU на выходе сделала бы отрицательные значения физически невоспроизводимыми, создавая систематическую (не связанную с аномальностью) ошибку реконструкции.
- Bottleneck (8 нейронов) - намеренное сжатие, вынуждающее сеть обобщать общие паттерны нормы, а не тривиально копировать вход (что произошло бы при слабом сжатии и сделало бы reconstruction error бесполезным для разделения классов).
- Loss: `MSE`, self-supervised — таргетом служит сам вход `X`, метки `y` в обучении не участвуют.
- Optimizer: Adam, `lr=1e-3`, фиксированное число эпох (без early stopping — для первой версии).
- Anomaly score = reconstruction error на объект (`MSE` по признакам, `axis=1`, не путать с усреднённым по батчу `MSE` для обучения).

Итерация по эпохам: 50 эпох -> PR-AUC 0.697 (loss curve ещё не вышла на полное плато) -> дообучение до 100 эпох -> **PR-AUC 0.720**, после чего кривая train/val loss вышла на плато без признаков переобучения - дальнейшее дообучение не проводилось.

### Официальный результат (полный набор, 31 признак): PR-AUC = 0.720**

Разделение классов по reconstruction error выразительное: медиана нормы ≈0.33, медиана фрода ≈7.56 (в ~23 раза выше).

## Финальное сравнение моделей

`test` не использовался ни разу до этого момента (ни для калибровки гиперпараметров, ни для отбора признаков) — единственный, финальный прогон уже обученных моделей с уже зафиксированными настройками.

| Модель | Признаки | PR-AUC (val) | PR-AUC (test) |
| --- | --- | --- | --- |
| Baseline | 4 отобранных | 0.739 | 0.773 |
| Isolation Forest | 31 | 0.55 | 0.583 |
| One-Class SVM | 31 | 0.32 | 0.334 |
| **Autoencoder** | 31 | 0.72 | **0.770** |

Все модели показали на test результат не ниже, чем на val (рост +0.01...+0.05) - признак того, что гиперпараметры не были переподогнаны под val, несмотря на малое количество фрод-примеров (236 в val), доступных для калибровки. Относительный порядок моделей на test идентичен val, что подтверждает устойчивость выводов.

**Ключевое наблюдение**: на test разрыв между Autoencoder (0.770) и baseline (0.773) практически исчезает - при 237 фрод-случаях в test разница в пределах шума. Это усиливает исходный вывод: baseline силён благодаря ручному, основанному на метках отбору 4 признаков - привилегии, недоступной в реальном unsupervised-сценарии. Autoencoder же достигает сопоставимого качества **без** этой привилегии, работая на полном, неотобранном наборе из 31 признака, что и составляет его практическую ценность.

**Выводы:**

- Все три модели официально сравнивались на едином, полном наборе из 31 признака (semi-supervised протокол, train без фрода) - это единственная переменная, которая не должна отличаться между экспериментами, для честности сравнения.
- Baseline - не участник сравнения моделей, а нижняя граница/sanity check: он намеренно использует метки для отбора 4 сильнейших признаков, что "нечестно" по отношению к моделям, работающим на всех 31 без разметки.
- Curse of dimensionality — сквозная тема проекта: и Isolation Forest, и особенно One-Class SVM резко теряют в качестве на 31 признаке по сравнению с ручным отбором 4 сильнейших (диагностировано отдельными вспомогательными экспериментами на урезанном наборе признаков).
- Autoencoder оказался единственной моделью, способной выучить полезные нелинейные комбинации из всех 31 признаков через градиентный спуск, не полагаясь на случайность (Isolation Forest) или сырую метрику расстояния (OC-SVM) - это и объясняет его превосходство при равных условиях.
- **Ограничения анализа**: val/test содержат всего 236-237 фрод-случаев каждый - метрики, особенно связанные с редкими диапазонами (например, доля фрода по часам суток на EDA), имеют широкие доверительные интервалы; выводы стоит воспринимать как показывающие порядок величины и направление эффекта, а не точные значения.

**Модель-победитель для дальнейшей работы (MLOps-обёртка): Autoencoder.**

## Калибровка порога (для продакшн-решения)

Порог откалиброван на `val` для перевода reconstruction error Autoencoder в бинарное решение "фрод/норма".

Экономика ошибок в fraud detection асимметрична: пропущенный фрод (False Negative) - прямая финансовая потеря для банка, ложная тревога (False Positive) - издержки на проверку/недовольство клиента, но не прямая потеря денег. Это оправдывает приоритет **Recall** над Precision, но не абсолютный, так как чрезмерно низкий Precision приведёт к загрузке call-центров и недовольству клиентов.

| Целевой Recall | Порог (reconstruction error) | Фактический Recall | Precision |
| --- | --- | --- | --- |
| $\ge$ 0.7 | **3.53** | 0.729 | **0.748** |
| $\ge$ 0.8 | 1.77 | 0.801 | 0.453 |
| $\ge$ 0.9 | 0.50 | 0.903 | 0.035 |

Между Recall 0.8 и 0.9 Precision обрушивается почти в 13 раз (0.45 -> 0.035), модель вынуждена захватывать множество пограничных нормальных транзакций, чтобы поймать последние, самые сложные случаи фрода.

**Выбранный порог: 3.53 (Recall=0.72, Precision=0.75)** - наиболее практичный компромисс, дающий рабочую нагрузку на систему проверки при сохранении высокого улова мошенничества. Порог сделан настраиваемым параметром сервиса, чтобы допускать пересмотр под конкретные бизнес-требования.

## MLOps: FastAPI + Docker

### Дизайн API

Один эндпоинт `POST /predict`, принимает батч транзакций (даже для одной — список из одного элемента).

**Request** (`BatchRequest`): список `Transaction` - `transaction_id` (опционально, для сопоставления ответов с запросами при обработке батча), `Time`, `V1...V28`, `Amount` - те же поля, что в исходном датасете, с базовой валидацией (`Time`, `Amount` $\ge$ 0).

**Response** (`BatchResponse`): список `PredictionResponse` - `transaction_id`, `is_fraud`, `anomaly_score` (reconstruction error), `threshold` - порог возвращается явно, чтобы клиент API мог применить свою политику к тому же скору, не завися от текущей конфигурации сервиса.
